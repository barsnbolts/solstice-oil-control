# Solstice GXP oil-control project site

Static HTML/CSS/JS, hosted by GitHub Pages. The public site compares current A/B/C concepts, their animations and interactive pan-context views, five saved-geometry fit scenarios, prototype STEP/DXF/GLB downloads, editable CAD source, project notes and sixteen manufacturer reference links plus separate Honda architecture notes. A digital scenario pass is scoped to modeled proxy surfaces; physical measurements do not gate the digital objective.

The `dist/` directory is the published edition. Pushes to `main` automatically deploy it with GitHub Actions. The open page checks for a new edition every minute and when returning to the tab, then offers a **Load update** button. A refresh never interrupts reading or video automatically.

To update from the local CAD project, first build a preview with `python3 site/build.py --preview`, have that exact edition independently reviewed, and complete the project package. Then run `python3 site/publish.py` from the parent workspace. The publisher verifies the current candidate, package receipt, accepted candidate hash, accepted site edition and portable bundle, then commits that exact `dist/` without regenerating timestamps or changing the reviewed edition. It fails closed if any identity differs. Complete the project checks/review/package first when CAD or project evidence changes. GitHub does not read the local workspace by itself; the update command publishes the accepted edition.

`build.py` and `publish.py` are workspace-side helpers. They require the full local project as the parent directory; a standalone GitHub clone can edit the public `dist/` files and push them directly. `check_dist.py` is intentionally independent of that private workspace and runs in GitHub Actions before every deployment.

The public ZIP preserves STEP/DXF/BOM directory relationships and contains editable source and animation sidecars. It is a curated export, not the complete local evidence/validation workspace. Local paths, private review logs and downloaded source archives are not published. The fit section includes five saved-geometry collision contexts and 30 context-specific 1 mm-sampled A/B/C vertical-withdrawal checks, summarized in six nominal route cards and bound to the same CAD report. Its linked assessment also summarizes 91 per-gate gravity-direction curves derived from the saved solids; these represent static mass-only torque, not oil response or measured car attitudes. An official GM 12601240 product photograph is displayed with attribution beside the explicitly assumed reconstruction; Vue service figures are labeled as application-unresolved or LY7/12666374 analogs. Other manufacturer references remain links. Google model-viewer 4.4.0 is vendored with its license to provide touch/keyboard orbit and gate playback.

All models are nominal prototypes. Pan/pickup/mount geometry and physical performance remain unverified. No order, fabrication release or engine-use acceptance is implied.

P5 quality checks run in the parent project: one shared dimensional source, generated register and summary, BOM regressions, full flat STEP/DXF equivalence, sampled independent gate/proxy clearance across five named contexts, gravity-torque regression checks, and exact media receipts. The public `catalog.json` drives the A/B/C selector and binds every detail/exploded/section asset to that candidate. Scenario and withdrawal cards plus their downloadable JSON are generated from the same saved-solid report; the portable validator also checks all gate counts, gravity vectors, angle curves and reported bias signs. Preview builds set `preview: true` in `version.json`, visibly label the page as pending review, and are rejected by the default public bundle check. Unchanged geometry validation and media are reused by content hash. Use `python3 site/build.py --preview` only for an unpublished local preview of a frozen candidate; publishing always requires accepted and packaged candidate identity.

The captive-pin access section adds three representative STEP scenes and a generated 312-check study: 26 pin ends, three cylindrical diameters and four assembly stages. These are continuous nose-sweep intersections. The 9.525/12.7 mm diameters derive from cataloged solid-rivet tool bodies, with complete tool/contact geometry and stainless heading applicability unknown. The stage comparison exposes the need to resolve pin heading before wall/cage joining; it does not qualify a physical forming sequence.

The source-accessory/saddle section adds three static review scenes and 104 combined setup assessments. Fixture collisions stop dependent tool checks; clear cases use a continuous upper bound only for declared whole-accessory rigid clocking. The manufacturer's mechanism, contact tool, powerhead and force/clamping remain outside the study. Raw manufacturer source files stay local; regenerating the accessory source model requires the linked manufacturer STEP matching the recorded hash. Insert CAD/cut-file dependencies remain in the public kit source.

The page begins with a work map separating checked digital studies, the latest accessory study, and open design work. Completed fit, sensitivity, removal and cylindrical-access studies use native expandable groups. Source illustrations, the note library, optional coupon and construction references also expand on demand. All results and download links remain present; direct section links open their containing groups, including on initial load and browser Back/Forward. Phone navigation uses six 44 px targets in two rows.
